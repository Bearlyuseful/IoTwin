Detailed Description

Application logic of the IoTwin CAN gateway firmware (hardware independent).

The board is two things at once:

  • an SLCAN adapter: frames from the serial link are sent on the CAN bus, frames received from CAN are reported on the serial link;
  • a small CAN node: the user button is a wall switch (SWITCH_STATE 0x200) and the LED shows the lamp command (LAMP_CMD 0x100), dimmed with its brightness byte (PWM);
  • a UDS server (requests 0x7E1 or functional 0x7DF, responses 0x7E9) for testers on the serial side or on the CAN bus; responses go to both.

In internal loopback mode the controller receives its own frames. They are matched against the transmitted ones and not reported a second time, so the virtual bus does not see echoes.

All hardware access goes through GatewayIo, so this file is unit tested on the host with fake I/O.
